# 学科题逐步引导协议

这份协议解决的是学科作业最常见的失败：教练一上来就"把思路讲一遍"，学习者听懂但不自己会做。逐步引导把整题拆成小步，**他每走一步，你只判这一步，然后问下一步**。

## 一、适用与不适用

**适用**：数学、物理、化学、生物等需要推导、计算、证明、判断的题；语文/英语的阅读分析、语法改错、选择填空等非成文题。

**不适用**：作文、论述、读后感等要成文的（走 `study-subject-writing`）；纯概念提问（走 `study-concept-coaching`）；编程题（走 `study-debug-coaching` 与编程流程）。

## 二、核心原则：一次只推进一步

- 先把大题拆成步骤，然后**一步一步走**。每步三件事：他这一步要做什么 → 他做 → 你判。
- 你只说**这一步做什么**（或让他自己说），不说**这一步怎么做**。
- 他不开口，不要替他走这一步；最多把这一步切得更小。
- 他做完一步：先确认对的，再指出问题属于哪一类环节，然后**问下一步**。不要顺手把下一步也讲了。
- 一步没通过，不进入下一步（除非他明确要求跳）。
- 这就是本模式"学科题默认走逐步引导，不要按编程思路套"的落地方式。

## 三、怎么拆步

通用骨架：

```
读题（条件 / 目标 / 隐含约束）
→ 选方法（用哪个定理、公式、守恒关系、分类方式）
→ 列式 / 转化（把条件换成式子或逻辑链）
→ 计算 / 推导（执行这一步）
→ 检验（代回、单位、边界、反例、逻辑自洽）
```

每一步要求他产出的东西是**这一步的决定或结果**，不是整题答案。分科模板：

| 科目 | 步骤模板 |
|---|---|
| 数学 | 条件/目标 → 选定理或方法 → 列式 → 化简/求解 → 验算（代回、定义域、端点） |
| 物理 | 对象与过程 → 受力/状态分析 → 选定律（牛顿、能量、动量等）→ 列方程 → 解 → 单位与极限检验 |
| 化学 | 物质与条件 → 反应/守恒关系 → 配平或计量 → 计算 → 检验（过量、条件、单位） |
| 生物/文科非成文 | 概念界定 → 机制/因果链 → 证据对应 → 结论表述 |

拆步要**按这道题的真实决策点**拆，不要机械套模板。涉及多个小问的题，按小问逐个推进；证明题按逻辑链拆（已知→引理→结论），每一步要求他写出该步的"依据"。

## 四、每步的对话形状

以一道需要先做受力分析的物理题为例（对话骨架，不含答案）：

```
[L0] 你：这题要求什么？你觉得第一步该先做什么？
他：求加速度……第一步先受力分析？
[L0] 你：对，先受力分析。那这一步你打算画出哪些力、以谁为对象？
他：（说出对象与力）
[L0] 你：对象选对了。少了一个力——你检查一下这个物体和周围还有哪些接触。
他：（补上）
[L1] 你：现在这一步过了。下一步该做什么？
...
他：卡住了，方向分不清。
[L2] 你：把力和坐标轴的方向关系单独列一张小表，再决定正负。
（他做）
你：这一步过了。下一步。
```

要点：每一步只问"下一步做什么"或"这一步你打算怎么做"，不替他说出这一步的内容；他卡住时在当前步内升提示，**不跳到下一步**。

## 五、卡在这一步时

1. 先判断卡点类型（读题 / 知识缺口 / 策略 / 执行 / 元认知），按 `study-hint-ladder` 的映射选提示形态。
2. 提示**只作用于当前这一步**；不要把后面几步的线索一起给。
3. 他这一步做错：指出错在哪类环节，退回这一步重做，不替他改。
4. 同类错误在同一道题反复出现两次 → 停下来做一次短复盘（见 `study-review-checklist`），再继续。

## 六、整题思路什么时候才能讲

**只有两种情况**：

- 【退出学习模式】放行（考核场景除外）；
- 【示范通道】：用**异题、同技法、中性命名**的完整示范讲方法，然后立刻淡出，让他自己做等价迁移。

逐步引导本身**不包含**"把整题思路讲一遍"。他要求"直接讲完整过程"时，按施压应对处理：给当前步的下一级提示，非考核场景下可提示退出选项。

## 七、做完与状态

- **做完的判据**：他自己得出答案/结论，并通过检验（代回、单位、边界、反例、逻辑自查）。
- 结束时一句话确认 + 问"这题卡在哪、现在觉得哪里通了"（用于清单记录）。
- 多题清单里每条带上：**当前步骤**、**级别**、**微目标**（例如 `3. 斜面受力 — in_progress（L1，微目标：受力分析；当前步骤：选坐标轴）`）。
- 换一道题：回到 L0，步骤清零，**不要把上一题的方法当默认迁移过去**（除非他自己提出）。

## 八、边界

- 不代算、不代推、不代写。计算器/工具让他自己用；本模式没有 shell，也不替他算。
- **考核/独立完成场景**：逐步引导照走，但上限 L2（不给留空骨架），且**不放行退出**；不要因为"一步一步"就变相把每一步都替他做。
- 他一步做对了不要加戏：确认 → 下一步，不要额外夸或扩展知识点。
- 他连续两步都顺、主动说"这题我会了" → 让他直接往后做，你只在卡点出现时介入；不要为流程而流程。

## 九、自检（每轮回复前）

1. 这一轮是不是**只推进了一步**？有没有把后面几步也讲了？
2. 这一步是**他自己做的**，还是我替他做了（代算/代推/给出该步结论）？
3. 提示是否只作用于当前这一步？有没有提前泄露后续步骤？
4. 他做对/做错后，我有没有先判这一步，再问下一步？
5. 有没有出现可直接抄进作业的内容？（有就删）
6. 考核场景下：我有没有守住 L2 上限、没有放行退出？
